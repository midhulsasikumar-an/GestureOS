ROOT CAUSE ANALYSIS: Why thumb=EXT + four curled can fail
First Rejection Point: Signal 3 — Direction Check (static_recognizer.py:389-411)
This is the most likely first rejection point for a real-world hand.
The direction check requires the thumb tip to be ABOVE both the thumb MCP and the wrist in image y-coordinates. This is a hard gate: if direction_score <= 0.0, the function returns None immediately.
Why it fails on real hands:
The check assumes the thumb points straight up in the image plane. In reality:
- The hand may be rotated (thumb points at 45° rather than straight up)
- The camera may be mounted at an angle
- The user may be in a non-upright position
- The thumb may point more toward the camera (z-axis) than upward (y-axis)
In any of these cases, thumb_mcp[1] - thumb_tip[1] can be very small or negative, making dy_mcp_ratio near zero or negative, which makes direction_score = 0.
Concrete example: If the hand is rotated 45° clockwise, the thumb tip might be at the same y-coordinate as the MCP. Then dy_mcp_ratio = 0, direction_score = 0, and the gesture is rejected at line 410-411.
Second Rejection Point: Signal 2 — thumb_extension_score < 0.55 (static_recognizer.py:384-387)
If the direction check passes but the thumb appears foreshortened in the 2D projection (e.g., hand rotated away from camera), the multi-feature score can drop below 0.55.
The penalty at gesture_utils.py:254-255 (halving the score when < 2 features are active) is particularly aggressive. If the separation ratio is low (thumb tip close to index MCP in the image), only 2 features might be active, and if one of those is marginal, the score can drop below 0.55.
Second Rejection Point: Confidence Threshold (static_gesture_engine.py:108-109)
Even if all three signals pass, the confidence formula 0.6 + 0.4 * thumb_score * direction_score can produce values below 0.85. For example, if thumb_score = 0.7 and direction_score = 0.5, confidence = 0.6 + 0.4 * 0.7 * 0.5 = 0.6 + 0.14 = 0.74, which is below the 0.85 threshold.
